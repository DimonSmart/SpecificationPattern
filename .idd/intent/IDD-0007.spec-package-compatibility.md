# IDD-0007.spec-package-compatibility

## Intent

Distribute the library as two compatible NuGet packages so consumers can use the LINQ core without EF Core and opt into the EF-specific query functionality when needed.

## Behavior

- `DimonSmart.Specification` is a standalone library for `IQueryable<T>` and `IEnumerable<T>` targeting .NET 10.
- `DimonSmart.Specification.EntityFrameworkCore` targets .NET 10 / EF Core 10, depends on the core package, and adds its own EF execution and query options without imposing EF dependencies on core-only consumers.
- A coordinated release publishes the core and EF Core packages with **the same version**. The EF package declares a dependency on the matching released core version.
- Package metadata, README and public samples describe actual available contracts and documented limitations; package version labels and release notes must not refer to missing documentation.
- Release artifacts are built from a version tag on the current mainline, are tested as a pair, and contain valid package identities, matching versions and EF-to-core dependency. Published versions must not be silently replaced.
- Publishing uses an authenticated, scoped release mechanism rather than committing a long-lived NuGet API secret to the repository.

## Non-goals

- Guaranteeing compatibility with earlier .NET or EF Core majors.
- Publishing different core and EF integration versions in one coordinated release.

## Acceptance Criteria

- Users can install just the core package for LINQ work, or the EF package and obtain both compatible dependencies.
- A release of both packages has matching semantic versions and a dependency on the same core version.
- Packaging succeeds with actual README and icon assets and no dangling documentation links.

## Verification

Check metadata and package dependency after packing both projects, validate a release tag's association with the main branch, and verify that the actual distributed NuGet assets correspond to the declared version.
