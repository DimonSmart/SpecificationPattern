# IDD-0005.spec-efcore-includes

## Intent

Allow immutable EF Core specifications to express navigation loading through typed and string Includes, with predictable composition, filtered branches and early rejection of incompatible plans.

## Behavior

- `Include(expression)` starts a typed chain that can continue with `ThenInclude(expression)` over reference or collection navigations. Typed expressions, including filtered collection operations, are retained for execution by EF Core.
- `Include("Books.Author")` accepts a dotted path through public CLR navigation properties or fields, including `IEnumerable<T>` collection elements. Empty, malformed or unknown CLR members are rejected when configuring the specification; EF Core validates that resolved members are mapped navigations during execution. Shadow-only navigation names and private members are not supported. A string Include cannot itself be extended with the typed `ThenInclude` chain.
- `Include(path, condition)` and typed conditional `Include`/`ThenInclude` do not add paths when disabled. A disabled initial Include starts an inactive chain: subsequent `ThenInclude` cannot activate it. A disabled intermediate `ThenInclude` leaves earlier paths intact while ending that continuation. Independently configured Include branches remain unaffected. Null selectors or invalid string paths are rejected even when disabled.
- Filtered collection Include recognizes exactly `Where`, `OrderBy`, `OrderByDescending`, `ThenBy`, `ThenByDescending`, `Skip` and `Take` in supported navigation expressions. Filtered collection Includes may continue into a child `ThenInclude`. Unsupported operators (such as `Select`, `Distinct`, arbitrary extension methods, derived-type casts or `EF.Property` shadow paths) do not silently fall back to a different query.
- Paths describing the same CLR navigation are reconciled between typed and string forms. Duplicate Includes are removed, a longer path subsumes a matching shorter prefix, and independent child branches are preserved. `And`/`Or` merge compatible navigation plans for the final combined query.
- Equivalent independently created filtered Includes **can be deduplicated** when their normalized expression trees demonstrably match; comparison respects operators, constants, captured inputs and parameter identity mapping. A filter with different behavior conflicts. Captured references are compared conservatively by identity and unsupported expression forms are not assumed equivalent. Filtered and unfiltered Includes on the same collection conflict. Conflict detection occurs during Include continuation and composition rather than allowing silent EF interpretation changes.
- Explicit Include plans cannot be combined with `Select`, `SelectMany`, or `WithProjectionOf` on the same EF specification. Project required navigation members directly in result selectors instead.
- Diagnostics may expose read-only Include path names; these names are not substituted for the original typed expressions during actual EF execution.
- Provider-specific SQL translation restrictions remain in effect (for example, combinations requiring SQL APPLY on SQLite may fail although the specification is valid).

## Non-goals

- Supporting shadow-only, arbitrary string, derived-cast, or dynamically invented navigation paths beyond the declared CLR path contract.
- Claiming identical SQL translation for every database provider.
- Using string diagnostics as executable Include definitions.

## Acceptance Criteria

- Typed and string Include variants produce the same relationships when their paths identify the same mapped CLR navigation.
- Compatible duplicate and prefix navigation plans are merged without losing independent branches.
- Independently authored structurally equivalent filtered Includes merge, while different filters and mixed filtered/unfiltered collection branches are rejected.
- Disabled initial or intermediate Include operations never unexpectedly create navigation loading.
- Projection incompatibilities fail immediately.

## Verification

Cover reference/collection ThenInclude, filtered includes with supported operators, identical and differing independent filter expressions, capture identity, string and typed path mixtures, invalid path/operator validation and representative SQLite translation behavior.
