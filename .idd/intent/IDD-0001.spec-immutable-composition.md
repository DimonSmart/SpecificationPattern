# IDD-0001.spec-immutable-composition

## Intent

A specification is a reusable immutable value describing query criteria and compatible query-level settings, not a mutable repository query builder. Consumers can compose independently authored business rules safely.

## Behavior

- The core exposes `Specification<T>`, `ISpecification<T>` and `ISpecification<TSource, TResult>`; EF Core exposes corresponding `EFCoreSpecification<T>` and read-only `IEFCoreSpecification` contracts. A repository may accept a read-only execution contract without demanding a concrete builder or a new repository abstraction.
- Factory-created or named specifications built through protected copy constructors can be reused. Configuring a filter, ordering, paging or EF option returns a new specification and does not mutate the original; a disabled conditional operation returns the original instance.
- `And` combines criteria with logical AND; `Or` combines with logical OR. Each specification's consecutive `Where` clauses are conjunctions. Combined predicates preserve short-circuit Boolean semantics without requiring in-memory query execution.
- An unrestricted specification (no `Where`) has a true predicate. `A.And(true)` preserves A's criteria; `A.Or(true)` permits every entity. Other compatible query settings are still merged, rather than discarded.
- Ordering, `Skip`, `Take`, and a keyset cursor are query-level settings applied to the full composed result (including an `Or`), not independently to each branch.
- Composition validates immediately: two independently configured ordering blocks, competing `Skip` or `Take`, two seek cursors, `SeekAfter` with `Skip`, conflicting EF tracking/splitting modes, or incompatible Include paths are rejected rather than silently choosing a side. A single ordering/paging setting may be contributed by either operand; compatible EF options merge. Query tags concatenate in order, named filter exclusions accumulate, and an all-filter exclusion dominates.
- `EnsureCompatibleWith` checks the same constraints without constructing a combined specification.
- `And`/`Or` are defined for compatible canonical source-stage specifications: zero or more `Where` steps, then optionally one contiguous `OrderBy`/`ThenBy` block, optional seek or `Skip`, and optional `Take`. Noncanonical arrangements such as a late `Where`, disjoint ordering blocks, or repeated paging are valid executable pipelines where otherwise permitted, but cannot be flattened into this composition contract.
- Arbitrary `And`/`Or` composition of projected specifications is not part of the public contract; compose source rules before projection (IDD-0003).

## Non-goals

- Automatically repairing incompatible query configurations.
- Automatically constructing a repository interface for users.
- Exposing mutable specification internals through read-only contracts.

## Acceptance Criteria

- Independent branches produce consistent results if their parent is reused later.
- `And`/`Or` return correct results for overlapping, disjoint, absent and unrestricted predicates.
- Incompatible combinations fail at construction/composition with meaningful errors, including conflicts arising from either operand; compatible options are preserved.
- Generic callers can execute through read-only contracts without casting to concrete specifications.

## Verification

Validate immutability and compatibility independently for LINQ and EF Core, including empty-`Or` semantics, ordering/paging/seek conflicts, EF Include conflicts, and the behavior of named derived specifications. See IDD-0002, IDD-0004, IDD-0005 and IDD-0006 for adjacent contracts.
