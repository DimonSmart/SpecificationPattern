# IDD-0002.spec-typed-query-pipeline

## Intent

Represent LINQ queries as deferred, immutable, strongly typed pipelines. Preserve operation order and the source/key/result types without library-generated boxing or conversion through `object`.

## Behavior

- A specification works over `IQueryable<T>` and `IEnumerable<T>`, including arrays and lazy collections. `BySpecification` applies its pipeline without eager enumeration; the `IEnumerable` convenience overload follows ordinary LINQ-to-Objects semantics and may return `IEnumerable` rather than `IQueryable`.
- Supported ordered operations include `Where`, `OrderBy`, `OrderByDesc`, `ThenBy`, `ThenByDesc`, `Skip`, `Take`, `Select`, `SelectMany`, and `SeekAfter`. Their effects follow fluent call order: `Take(10).Where(p)` filters the first ten items; it is not equivalent to `Where(p).Take(10)`.
- `OrderBy<TKey>`/`OrderByDesc<TKey>` establish a primary sorting block using the actual selector/key type. `ThenBy<TKey>`/`ThenByDesc<TKey>` append keys only to an immediately preceding active ordering block in the current typed stage. Intervening active `Where`, `Take`, `Skip`, or a new stage prevent continuing the previous block. Another `OrderBy` starts a new primary ordering block rather than implicitly behaving like `ThenBy`.
- Sorting uses the corresponding provider `Queryable` operators; key selectors are retained as typed expression trees. Naturally typed numeric/date keys, projection results and keyset cursor values must not be erased into `object[]`, untyped delegates or `Expression<Func<T, object>>` by the library. Explicit object casts supplied by a caller are not rewritten and need not be translatable by a provider.
- Optional overloads of `Where`, sorting, `Skip` and `Take` take a Boolean condition. A false condition appends nothing, leaves the immutable instance unchanged and does not interrupt an ordering block; a true condition behaves like the normal operator. Even disabled operations validate invalid null expressions and negative paging counts. Enabled `ThenBy` requires a live ordering block.
- The type-changing operations begin new typed stages; subsequent operators work with the current element type, not the original source type (IDD-0003).
- `PipelineSteps` is the shared, read-only snapshot for diagnostics, not executable query state. Steps expose index, stage, operation, input/output CLR types, original expression metadata and keyset-ordering marker. Ordering steps expose `IsOrdering` and `Direction`; `Skip`/`Take` expose `Count`; `Direction` is valid only for ordering steps.
- Observers cannot mutate the specification via the diagnostic snapshot. A current query's evaluation is determined by its pipeline, not by regenerated diagnostic objects.

## Acceptance Criteria

- Equivalent operators applied in different orders preserve normal LINQ ordering semantics where their effects differ.
- Composite typed ordering matches LINQ/EF results without hidden library-generated boxing or client-side fallback.
- Illegal `ThenBy` placement fails immediately; disabled conditional operations do not alter ordering continuity.
- Snapshot inspection reflects source and projected pipelines and cannot change execution.

## Verification

Check multi-key ascending/descending sorting, repeated primary ordering, conditional enablement/disablement, invalid arguments, lazy enumeration, projected stages and diagnostic direction/count/typing. Keyset-specific requirements belong to IDD-0006.
