# IDD-0003.spec-projections-and-criteria

## Intent

Allow specifications to change the shape of query results and to evaluate only membership criteria when callers need filtering or counts independent of specification paging.

## Behavior

- `Select<TResult>` and both `SelectMany` forms are deferred typed query operations. A projection may produce entities, DTOs, anonymous objects, scalars or other CLR result types; additional `Where`, sorting, paging, seek and projections can follow on the new element type. The result's type is retained end to end without forced materialization or expression compilation.
- `WithProjectionOf` appends an independently reusable projected pipeline after the source pipeline, retaining the projection pipeline's own filters and paging as well as its mapping. Both inputs remain unchanged. In EF Core, compatible root query options merge, but explicit `Include` plans cannot be combined with a projection (IDD-0005).
- `BySpecificationCriteria` runs only the filtering `Where` criteria and required type-changing `Select`/`SelectMany` stages of the specification. It ignores the specification's sorting, `Skip`, `Take`, and `SeekAfter` boundary (including its generated internal seek predicate). A late `Where`, even one configured after paging, remains a criterion.
- Criteria-only application does not strip or rewrite operations already present on the caller's incoming `IQueryable` (such as `Where`, `OrderBy`, `Take`, or `Include`). For projected specifications, criteria-only results and counts concern the final projected element type.
- For EF Core, criteria-only application additionally omits specification-provided Includes, tracking, query splitting, auto-include overrides and tags; database global query filters remain active except for explicitly disabled global filters (all or named). See IDD-0004.
- `IsSatisfiedBy(candidate)` evaluates the in-memory `Where` criteria of `Specification<T>` or root `EFCoreSpecification<T>` for a single non-null entity, ignoring ordering, paging, seek and all EF-only behavior. An unrestricted specification matches every non-null entity. Matching must short-circuit predictably, and repeated evaluations can reuse a lazily compiled criterion.
- Provider-specific predicates (for example EF Core SQL `LIKE`) may not be usable via `IsSatisfiedBy`, which requires an in-memory-compatible predicate; the method does not emulate database translation.

## Non-goals

- `And`/`Or` composition between arbitrary projected specifications (compose source-stage rules first).
- Silently projecting Include-based entity loading or emulating unsupported provider queries in memory.

## Acceptance Criteria

- Two specifications can independently reuse the same typed projection, including a projection with post-projection filters/paging.
- Criteria-only counts can differ from paginated query results in the expected direction without altering the caller's source query.
- When a projected pipeline contains late filters, criteria-only retains those filters and projections while omitting its paging.
- `IsSatisfiedBy` matches criteria-only membership for supported in-memory predicates, including unrestricted and noncanonical pipelines.

## Verification

Cover source and projected LINQ queries, EF Core SQLite queries, projection reuse, criteria-only behavior after prior incoming query operators, provider filter exceptions, and repeated in-memory evaluation with short-circuit predicates.
